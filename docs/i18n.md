# Languages

Status: implemented. The game speaks English, German and Indonesian; the kids' guide (`learn/`)
in English and German, in the same words. More languages are a catalog each.

## Choosing one

The settings' first row (`game/settingsmenu.js`) lists every language by its own name; a click
switches at once, without a reload, and is kept in `crawler.settings` (`language`). Until one is
chosen the game speaks the browser's (`navigator.languages`: the first it knows, else English).
`?lang=de` in the address wins over both (the guide's game window uses it). The guide follows
its own choice (`kids.lang`); the game's link to the guide passes the game's language.

`src/i18n/i18n.js startLanguage` decides; the module loads the catalog before any other module
runs (a top-level `await`), so nothing ever draws in the wrong language. Node (the tests) and the
world worker always speak English: neither shows words.

## How the code says things

The English text in the code is the message, and its own key:

```js
import { tr, msg, noun, phrase } from '../i18n/i18n.js';
setStatus(tr('Inventory is full'));
setStatus(tr('{item} on quick bar slot {n}', { item: itemName(slot), n: i + 1 }));
tr('{n, plural, one {Defeated # enemy} other {Defeated # enemies}}', { n })
```

- **`tr(text, params)`** says it now, in the language of the moment.
- **`tc(context, text)`** for the same English meaning two things (`tc('toggle', 'Off')`); the
  catalog has it as `'toggle|Off'`.
- **`msg(text)`** marks a text that is said later (`tr(x)` where it shows): data tables, labels.
- **Data tables** (item names, enemy kinds, affixes, trial names ...) keep their English and are
  said with `tr` where they show; `src/i18n/sources.js` lists the tables, so the tool knows them.
  A new table of texts goes there.
- **`index.html`**: an element marked `data-t` has its content translated (`data-t="title
  aria-label"`: those attributes; `text` the content). Mark only what the code does not fill in
  (`src/i18n/dom.js`). Use characters, not entities (`…`, not `&hellip;`).

A message is a plain string: never build it with `${}`. Pass the values as parameters, so
another language can put them where it needs them.

### What a message may say

| | |
|---|---|
| `{name}` | a parameter: a number (in the language's digits: `1,5` in German), text, words (below) |
| `{x:form}` | a noun's form, by language: English `the`, `a`, `pl`, `it`, `this`, `is`, `they`, `cap`, and for people `he`, `him`, `his`; German `der` / `den` / `dem` / `des`, `ein` / `einen` / `einem`, `mein`, `sein`, `ihr` ..., `dieser`, `er` / `ihn` / `ihm`, `pl`, `cap` (the case said by the masculine word). With a capital (`The`, `Der`) it starts with one |
| `{n, plural, one {...} other {...}}` | by the language's plural rules (`Intl.PluralRules`); `#` the number, `=0 {...}` exact |
| `{x, select, m {...} f {...} other {...}}` | by a text, or a noun's gender (`m`, `f`, `n`, `pl`) |

German puts `zu dem` together as `zum` (and `vom`, `im`, `beim`, `zur`, `ins`) after a message is
said (`src/i18n/de/grammar.js finish`).

### Words kept for later

What is kept (saves, the chronicle, a friend's news, a quest) is never words in one language,
but words to say: plain JSON that `say(x)` turns into the language of the moment.

| | |
|---|---|
| `'Town'` | in the chronicle, quests' `where` and the like: an English message (said with `tr`) |
| `phrase(text, params)` | `{ t, p }`: a message and its parameters, which may be words again |
| `noun('Lantern')` | `{ noun }`: a thing, for its forms (`{thing:den}` is "den Kompass", "die Laterne") |
| `person('Ada', 'f')` | `{ name, g }`: somebody, by name (`{who:him}` is "her") |
| `{ t, p, of: 'kind' }` | a phrase that is a noun of its parameter's gender: "Wächter-Spinne" is feminine |
| `itemWords(item)` | `{ item }`: an item, said by its name (generated or not) |

A world saved in German loads in English and the other way round, and friends playing together
each read their own language (`PROTOCOL` 14: news carries words; `cleanWords` checks them).
Quests made before this kept English sentences; those stay English.

### Nouns and their gender

German needs a noun's gender to say it in a sentence, so a noun's entry in a catalog is an
object: `'Lantern': { text: 'Laterne', g: 'f', pl: 'Laternen' }`. Also `obl` for a weak noun
(`'Oktonaut'`: "einem Oktonauten"), `dat` for an odd dative plural, `adj` for a name that starts
with an adjective (`'Verschüttete Ruinen'`, adj `'Verschüttet'`: "in den Verschütteten Ruinen").
Everything the code passes to `noun()` (items, enemies, places, landmarks, roles) has one.
People out in the world have a gender from their name (`core/npcs.js isShe`): a role or a relation
is a woman's where German has one (`'she|hermit'`: "Einsiedlerin").

### Generated item names

An item keeps its English name (`gen.name`: saves, the network). To say it in another language
`core/gear/names.js wordsOf` finds the words it was made of again, and the language's
`names.js` (`src/i18n/de/names.js`) has a word for each, in the same order, and puts them
together: German adjectives take the base's gender ("Matschiges Langschwert", "Matschige
Armbrust"). Change an English word together with its translations; a name whose words are gone
shows in English.

### What stays English

The world names (they are made from the seed and give it back: a friend types one in), the
developer tools (`?dev=1`: the dev panel and the developer commands, their help and answers),
`console.warn`s and errors. The bosses' names and the made-up kinds (Stunder, Shraps, Spicy,
Wolla, Wolk, Squirtle, Mecked) are the same in German.

## The glossary

`src/i18n/glossary.js`: the game's important words and what they are in each language (cube:
Würfel, depth: Tiefe, quest: Auftrag, enemy: Monster ...), with a note on each, and the names of
the game's things (from its tables). `node tools/i18n.mjs --glossary` prints it. Look a word up
there before translating, and add a new important word there first. The tool checks that every
message saying a glossary word in English says the glossary's word in the translation, and that
the guide's German never calls a thing by its English name (`learn/README.md`).

## Keeping the translations up to date

```sh
npm run i18n                     # node tools/i18n.mjs: what is missing, unused or broken
node tools/i18n.mjs --todo de    # the missing German messages, ready to fill in, by file
```

`npm test` fails until every message has every translation (`tests/i18n.test.js`), so a change
of English text is translated in the same change:

- **missing**: a message without a translation. Write it into the part of the catalog it belongs
  to (`src/i18n/de/ui.js`, `items.js`, `enemies.js`, `quests.js`, `trials.js`).
- **unused**: a translation of a message that is gone. Usually the English changed: the tool
  names the likely new message; move the translation over and fix it.
- **broken**: a translation that does not parse, leaves out a parameter or adds one, uses a form
  the language does not have, or differs in markup; a message built with `${}`; `tr` imported
  under another name.
- **glossary** / **guide**: see above.

While playing, `window.__game.i18n.missing` lists what was said without a translation.

## Another language

1. Add it to `LANGUAGES` (`src/i18n/i18n.js`, by its own name) and to `loaders`.
2. Make `src/i18n/<code>/`: `index.js` (like German's: `{ code, grammar, names, messages }` and
   its `parts`), a `grammar.js` (`form(noun, name)`, `forms`, and `finish` if it contracts), the
   catalog parts, and `names.js` for the item names (or leave `names` out: they stay English).
3. Add its words to the glossary (`de` patterns are per language: add the new code's).
4. `node tools/i18n.mjs --todo <code>` lists everything to translate.
5. The guide is in English and German only (`learn/lang.js`); a language for it is its own job.
